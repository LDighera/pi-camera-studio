# Pi Camera Studio verification record

This record separates locally verified behavior from intended support and
unproven behavior. It contains no user-specific home paths or transient test
artifact locations.

## Release identity

- Application version: `0.1.0a1`
- GitHub release tag: `v0.1.0-alpha.1`
- Public repository: <https://github.com/LDighera/pi-camera-studio>
- Release maturity: alpha

## Verified platform

The hardware proofs performed on 2026-07-14 and 2026-07-17 used:

- Raspberry Pi 5, `aarch64`
- Debian GNU/Linux 13 (trixie), arm64
- Linux `6.18.34+rpt-rpi-2712`
- Raspberry Pi Camera Module 3 / Sony IMX708; Picamera2 reported a 4608×2592
  sensor raster
- an HDMI touchscreen setup with a 1024×600 preferred panel mode, operated in a
  1920×1080 Wayland compositor mode
- a C-Media/PCM2902 USB audio capture device exposed through PipeWire and ALSA;
  PipeWire reported it as the desktop's default audio source during the final
  release-candidate recording

Current 64-bit Raspberry Pi OS Desktop is the intended public target, but it was
not separately tested from this Debian 13 system. Other boards, cameras,
architectures, operating systems, and desktop stacks remain unverified.

## Automated and structural evidence

The following checks were run from the release tree on 2026-07-17:

```sh
scripts/release-check
```

Results:

- 33/33 unit tests passed without skips, including real model loading and
  inference.
- Python compilation, POSIX shell parsing, and ShellCheck passed.
- The repository desktop template passed `desktop-file-validate`.
- The bundled model produced the expected SHA-256 recorded above.
- A wheel and source distribution were built from an isolated copy of the
  release tree, and their required code, model, documentation, license, and
  entry-point members were checked.
- A scan of the release tree found no private user name, user-specific
  development path, credential pattern, display EDID name, or transient
  hardware-proof path.

The installer lifecycle was also exercised under isolated temporary `HOME` and
`XDG_DATA_HOME` paths containing spaces. The check confirmed that:

- the full runtime and bundled model are copied;
- generated bytecode is not copied;
- the installed desktop entry contains the isolated user's absolute launcher
  path and passes `desktop-file-validate`;
- the installed launcher reports version `0.1.0a1`;
- rerunning `install.sh` completes as an in-place managed upgrade; and
- uninstall removes only the managed runtime, launcher, and desktop entry while
  leaving a synthetic media sentinel untouched.

## Hardware and interface proof

The 2026-07-17 final proof used an isolated copy of the release-candidate tree
and exercised the actual GUI buttons for all four workflows. It established:

- a visually reviewed, fully decoded 4608×2592 JPEG still;
- a visually reviewed H.264 1920×1080 MP4 with 103 video frames and a 3.565
  second container duration;
- an AAC LC, 48 kHz audio stream captured from the desktop's default USB
  microphone, with 151 audio frames and 3.235 seconds of positive duration;
- decoded audio samples measured by FFmpeg at -49.8 dB mean and -38.6 dB peak,
  establishing a non-silent but low-level test recording;
- two visually reviewed 4608×2592 stop-motion frames and a visually reviewed
  one-second H.264 render containing exactly two frames;
- live NanoDet inference and promotion of an annotated detection snapshot; and
- successful close-during-capture checks for an in-progress full-resolution
  still and live detection, with bounded shutdown and no temporary files left
  behind.

Separately, all four application tabs were rendered and visually inspected at
1920×1080 in the real Wayland desktop session. Controls and status text were
readable, the Video tab exposed the default desktop audio input, and the
application reported the connected camera dynamically. The test scene was
physically tilted; that is the camera's mounting orientation, not evidence of
file rotation or decoding failure.

Positive object detection was separately checked during the earlier hardware
proof with OpenCV's `dog416.png` fixture, SHA-256
`61db162464c0770138c5136af0e999ce3b6556244cec257945427396480d9caf`.
Three repeated runs at the application's default 0.35 confidence threshold gave
the same bicycle, truck, person, and dog detections, with visually aligned
boxes. The final live scene produced a `car` false positive at 38% confidence;
it was explicitly excluded from any accuracy claim. That live result verifies
only inference, annotation, and snapshot plumbing.

The tested Wayland compositor rejected Picamera2's OpenGL preview with
`EGL_BAD_ALLOC`; the application's software Qt preview fallback ran
successfully. The non-Wayland OpenGL path was not part of that proof.

## Verified safety properties

- The application contains no telemetry, upload path, account integration, or
  runtime model download.
- The camera preview starts at GUI launch. Microphone inputs are enumerated at
  launch, but audio capture starts only when the user starts a recording with
  audio enabled.
- Images are decoded and dimension-checked before promotion to a final filename.
- MP4 promotion requires a video stream and, when audio is requested, a
  positive-duration audio stream with a readable packet.
- Stop-motion sequences with missing frame numbers are rejected before render.
- Object detection is limited to the model's 80 COCO categories and provides no
  named-person or unique-identity recognition.

## Remaining uncertainty

The following are unproven or insufficiently qualified for a stable release:

- current Raspberry Pi OS Desktop as distinct from the verified Debian 13 host;
- boards and cameras outside Raspberry Pi 5 plus IMX708;
- long recordings and sustained thermal/storage behavior;
- disk-full handling and device hot-unplug during capture;
- suspend/resume and concurrent detection plus video recording;
- recorded end-to-end touchscreen gesture behavior across compositor setups;
- subjective microphone level and A/V lip-sync; and
- detector performance outside the positive fixture and small live-scene
  sample.

For these reasons `v0.1.0-alpha.1` must not be described as a general-purpose,
stable, or safety-critical camera release.
